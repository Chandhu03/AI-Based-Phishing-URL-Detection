Evaluating URL-only phishing detection, honestly.

We trained a model that reads only a link’s host name, tested it on websites it had never seen, and compared it with what came before. This page reports what held up and what did not. All figures are generated from the evaluation reports in the repository at build time.

Summary

  • Useful, not decisive. On held-out PhiUSIIL domains the shipped model reaches ROC-AUC {{m:engine:/test/engine_shipped/phiusiil_test/roc_auc|f3}} and catches {{m:engine:/test/engine_shipped/phiusiil_test/at_high/recall|pct0}} of phishing at its “high” threshold with {{m:engine:/test/engine_shipped/phiusiil_test/at_high/fpr|pct1}} false alarms.
  • Weaker on different data. On held-out Hannousse domains ROC-AUC is {{m:engine:/test/engine_shipped/hannousse_test/roc_auc|f3}} and false alarms at “high” rise to {{m:engine:/test/engine_shipped/hannousse_test/at_high/fpr|pct1}}.
  • Fewer sites than URLs. Counted once per host instead of once per URL, recall at “high” is {{m:sites:/tests/phiusiil_test/per_host/at_high/recall|pct0}} on PhiUSIIL and {{m:sites:/tests/hannousse_test/per_host/at_high/recall|pct0}} on Hannousse (details).
  • A shortcut, found and excluded. In PhiUSIIL every legitimate URL is a bare https://www. homepage; a one-line rule scores F1 {{m:phase3:/shortcut_probe/phiusiil_test/f1|f3}} there. The model therefore reads only the host name.
  • The model is one input. In the workspace it sits beside explainable rules, and a verdict never says a link is safe.

Data

Two public datasets, both CC BY 4.0, verified by SHA-256 on download. Only the URL text and label are used. Supplied features derived from page content are ignored, because a URL-only detector cannot see them.

Method

  • Split by owner. Every URL is grouped by its registrable domain (Public Suffix List), and the split is 70/15/15 by a salted hash of that domain. No domain appears in two splits, so the test measures new sites, not memorised ones.
  • Choices on validation only. Hash size, regularisation, quantisation, calibration and thresholds were all chosen on the validation split. Each test set was scored once, afterwards.
  • Model. Hashed character 3–5-grams of the host name (one leading “www.” removed), L2-normalised, with logistic regression; 216 buckets, int8 weights, Platt calibration. It runs in the browser, and a parity test checks the browser’s scores against Python to 1e-9 on 318 reference hosts. Its id, {{m:engine:/export/model_id|id}}, is derived from the SHA-256 of its weights, calibration and thresholds; the browser checks it before using the model. Host names outside the international domain name standard (IDNA2008) are not scored, because training dropped them.
  • Thresholds. “High” is the score giving at most 1% false alarms on validation; “elevated” gives at most 5%. Validation is about 95% PhiUSIIL, which matters below.

A dataset shortcut

In PhiUSIIL, legitimate URLs are popular homepages written as https://www.domain with no path. A rule with no machine learning — “legitimate if https, starts with www. and has no path or query” — scores F1 {{m:phase3:/shortcut_probe/phiusiil_test/f1|f3}} on PhiUSIIL but {{m:phase3:/shortcut_probe/hannousse_test/f1|f3}} on Hannousse. Any model that can see the scheme, a “www.” prefix or the path learns that artefact. The shipped model sees none of them; path and structure signals are handled by the explainable rules instead.

Counted once per site

The tables above count every URL. The model reads only the host name, so all URLs on one host get the same score, and a site with hundreds of URLs in a dataset counts hundreds of times. In the Hannousse test set one domain alone is {{m:sites:/tests/hannousse_test/largest_domain_share|pct0}} of the URLs. Across datasets

Trained on one dataset and tested on the other’s held-out domains, the same recipe reaches ROC-AUC {{m:engine:/transfer/train_phiusiil_test_hannousse/roc_auc|f3}} (PhiUSIIL to Hannousse) and {{m:engine:/transfer/train_hannousse_test_phiusiil/roc_auc|f3}} (Hannousse to PhiUSIIL). Expect performance on your own traffic to be closer to these figures than to the in-dataset ones.

Calibration and thresholds

Scores are calibrated with Platt scaling on validation. Expected calibration error on the test sets is {{m:engine:/test/engine_shipped/phiusiil_test/ece_10|f3}} (PhiUSIIL) and {{m:engine:/test/engine_shipped/hannousse_test/ece_10|f3}} (Hannousse); Brier scores are {{m:engine:/test/engine_shipped/phiusiil_test/brier|f3}} and {{m:engine:/test/engine_shipped/hannousse_test/brier|f3}}. Because validation is mostly PhiUSIIL, the “high” threshold’s 1% false-alarm target holds there but not on Hannousse. In the workspace, a high model score alone yields “Suspicious”, never “High risk”; it takes rule-based evidence as well. On domains in the brand reference list, the model score is not used at all.

The original prototype

The course-project app displayed “98.6% accuracy”. That figure came from a model trained on 48 page-content features of a different dataset, not from the Random Forest that scored links, which was trained on synthetic URLs. Measured the same way as above, that Random Forest catches {{m:phase3:/experiments/A_host_phiusiil/models/reference_demo_model/test/phiusiil_test/at_app_default_0.5/recall|pct1}} of phishing on held-out PhiUSIIL domains at its default setting. It is kept in the repository as a reference baseline only.

Limitations

  • Distribution shift. PhiUSIIL’s legitimate URLs are popular homepages; everyday legitimate links are far more varied, so real false-alarm rates will be higher.
  • No time dimension. Neither dataset has timestamps, so drift over time is unmeasured, and phishing infrastructure changes quickly.
  • Text only. A URL-only model cannot recognise a compromised legitimate site, content on shared hosting, or a convincing newly registered domain.
  • Unknown provenance. Neither dataset documents its URL sources, so label noise cannot be quantified.
  • Popular sites can score high. Login and account hosts of real services (and some popular sites such as large shops) resemble phishing hosts to a model trained on these datasets. On domains in the brand reference list the score is ignored; elsewhere a high score alone gives “Suspicious”, never “High risk”.
  • Brand list. The brand reference list behind the impersonation checks is curated by hand and covers a few dozen commonly impersonated brands, not every brand.
